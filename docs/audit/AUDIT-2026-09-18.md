# Audit — 2026-09-18 — Phase 3 backend

Findings from building and reviewing the marketplace core. Kimi's findings live in `HANDOFF.md`;
these are mine, against my own work, and each is fixed in the commit named.

## C.1 — Organisation role guards admitted outsiders (High, fixed)

`private.org_role()` returns NULL for someone who is not a member, and every guard was written as
`private.org_role(org, uid) <> 'owner'`. In SQL that is NULL, not true, so the `IF` never fired:
**any signed-in user could invite members to any organisation, change roles, register its vehicles
and dispatch its jobs.**

Found by the two pgTAP assertions that expect an outsider to be refused — which is the argument
for writing deny tests rather than only allow tests. Fixed by making every comparison null-safe
(`IS DISTINCT FROM`, or `coalesce(role::text, '')` against a list). The RLS policies on
`organizations` were already safe: a NULL in a `USING` clause filters the row out.

**Carry forward:** any future `private.*_role()` helper that can return NULL needs the same
treatment, and its deny test written first.

## C.2 — The provider feed disclosed the exact pickup address (Medium, fixed)

`provider_feed()` returned `pickup_label` — the address the customer typed — to every matched
provider. PR-11 says the card carries an *approximate pickup area*, with the exact address revealed
only after assignment. Fixed by returning the city, a point rounded to two decimal places (about a
kilometre) and the photos; the function was replaced, so the shape changed for Kimi.

## C.3 — An attempt limit that could not bite (Medium, fixed before merge)

The first draft of `verify_pin` raised on a wrong PIN. Raising rolls the transaction back, and the
attempt counter with it, so the five-attempt limit would never have applied. A wrong PIN now
returns `{verified, status, attempts_remaining}`; structural failures still raise.

## C.4 — The response-time metric excluded the fastest answers (Low, fixed)

`recompute_reputation` measured time-to-first-offer with `o.created_at > req.published_at`. An
offer in the same timestamp was dropped — and since the metric selects for speed, the offers being
excluded were the quickest ones. Now `>=`.

## C.5 — `request-media` had no bucket (Low, fixed)

`create_request(… media_paths)` stored paths into a bucket that did not exist, from the requests
migration until the proofs one.
