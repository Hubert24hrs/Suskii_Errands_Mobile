# Audit — 2026-09-27 — whole repository, store readiness

The fourth pass (2026-09-22d) audited the repository as a codebase. This one audits it as a
**product about to be submitted to two stores**: the question is not only "is the code right" but
"what happens on a real handset, signed in against a real Supabase project, in front of an App
Review or Play policy reviewer". Kimi's M9 wiring (2026-09-23 → 25) changed that question, because
for the first time a flavor with credentials exercises the Supabase implementations end to end —
and several things that were harmless on mocks are not harmless there.

The user authorised Claude Code to edit `apps/` and `packages/` for this pass (normally Kimi's).
Every change in those paths is written up in `HANDOFF.md` so Kimi inherits the reasoning.

## Critical

### Y.1 — A release build cannot reach the network (Critical)

**What.** `android/app/src/main/AndroidManifest.xml` declares no permissions at all.
`android.permission.INTERNET` exists only in `src/debug` and `src/profile`, which is the Flutter
template's default, and none of the plugins the app uses (`supabase_flutter` and its
dependencies) contributes it to the merged manifest.

**Consequence.** Every debug run and every test works, and the first release build — the one that
goes to the Play Store — fails every Supabase call with a socket permission error. The mock flavor
hides it completely, which is why seventy screens of review never saw it.

**Fix.** Declare `INTERNET` (and only the permissions the app actually uses, Y.10) in the main
manifest.

## High

### Y.2 — Session tokens in plain `SharedPreferences` (High)

**What.** `Supabase.initialize` is called without `authOptions.localStorage`, so `supabase_flutter`
persists the session — refresh token included — in `SharedPreferences`.

**Consequence.** The spec (security.mobile) and MASVS-STORAGE-1 both require tokens in
Keychain/Keystore-backed storage. A refresh token in an XML file is readable from any backup that
includes app data and from any rooted device.

**Fix.** A `LocalStorage` backed by `flutter_secure_storage`; Android backup of app data disabled
for the same reason.

### Y.3 — The next person on the handset sees the last person's data (High)

**What.** The data providers (`walletSummaryProvider`, `activeJobsProvider`, `myDisputesProvider`,
`referralSummaryProvider`, `supportTicketsProvider`, ~40 more) are plain, non-`autoDispose`
providers that nothing invalidates on sign-out, and `ModeController` refuses to re-seed once
seeded.

**Consequence.** On a shared handset — common in the markets this app launches in — user B signs in
after user A signs out and sees A's wallet balance, active jobs and tickets until each screen is
pulled to refresh; B also inherits A's active mode. Sign-out already clears idempotency keys for
exactly this reason (M3.14); the data was missed.

**Fix.** A `sessionUserIdProvider` that every repository provider watches, so a change of user
rebuilds the whole data graph; `ModeController` re-seeds per user.

### Y.4 — The Profile tab crashes for every new user (High)

**What.** `profiles.display_name` is `NOT NULL DEFAULT ''` and nothing in the app sets it. The
mapper turns it into `''`, and `ProfilePage` calls `displayName.substring(0, 1)`; so does
`SProviderCard`.

**Consequence.** `RangeError` on the Profile tab for every account created through phone OTP — which
is every account. On mocks every fixture user has a name, so it never showed.

**Fix.** A safe initial, and an editable name on the profile (the `UPDATE` grant on `display_name`
has existed since Phase 2).

### Y.5 — Proof of completion proves nothing (High, both layers)

**What.** `ProviderJobExecutionPage._addProof` submits
`'<jobId>/proof-<millis>.jpg'` to `submit_proof` without uploading anything, and `submit_proof`
records the path without checking that an object exists in `job-proofs`. The idempotency key is
`proof-<jobId>-<kind>`, so a provider's second photo replays the first.

**Consequence.** The category's `proof_requirements` trigger is satisfied by a string. A customer
"reviews" proof that is not there, and a dispute officer later finds no evidence behind the row.

**Fix.** Capture (camera or gallery) and upload to `job-proofs/<request_id>/…` before calling the
RPC; one key per capture; and `submit_proof` refuses a path with no object behind it
(`ERR_PROOF_REQUIRED`, which the catalogue already has).

### Y.6 — KYC documents are `upload://mock/<timestamp>` on a real backend (High)

**What.** `provider_kyc_step_forms.dart` builds upload references with `_newUploadRef()` on every
flavor, and `SupabaseProviderKycRepository` submits them through `submit_kyc_step`.

**Consequence.** A provider completes the ID-document, vehicle and credential steps on a real
project and a verification officer reviews references to files that were never sent.

**Fix.** Capture and upload to `kyc-docs/<uid>/…` (the bucket is write-only for clients, which is
the point), and submit the object path.

### Y.7 — A payment cannot be completed on the device (High)

**What.** When `start_payment` + `get_payment_checkout` return a hosted checkout URL, the payment
page renders it as `SelectableText`. There is no way to open it.

**Consequence.** Card and mobile-money payments — the only rails at launch — need the customer to
copy a URL into a browser by hand. The amount shown is also `agreedPrice`, not what the server
charged (the item float, its surcharge and a promo all change it).

**Fix.** Open the checkout with `url_launcher` (https only), and show the server's amount.

### Y.8 — Placeholder content in production builds (High, store)

**What.** On every flavor, including one pointing at a real project:
"Demo build: any 6-digit code signs you in" under the OTP field; Google and Apple buttons rendered
disabled over "Coming in the next milestone"; an MFA screen that says "this is a preview" forced
after every sign-in; "Simulate offline (demo)" on the profile; "Capture document (demo)" and
"Attach a file (demo)" in KYC; a hard-coded version string `0.1.0`.

**Consequence.** App Review guideline 2.1 (incomplete, placeholder content) and Play's minimum
functionality policy are the most common first-submission rejections, and each of these is one.
The demo OTP line is also simply false against a real project.

**Fix.** Demo affordances render only when the app runs on the mock layer; social sign-in and MFA
are hidden until they exist; the version comes from the platform.

### Y.9 — Account deletion and data export do nothing on Supabase (High, store)

**What.** `SupabaseSettingsRepository.requestAccountDeletion` and `requestDataExport` throw
`ERR_FEATURE_UNAVAILABLE`, because no RPC exists (CR-20260923-07, open since 2026-09-23).

**Consequence.** App Store guideline 5.1.1(v) and Google Play's account-deletion policy both require
in-app deletion. The button exists and fails.

**Fix.** `request_account_deletion` / `cancel_account_deletion` / `request_data_export`, a grace
period from remote config, and a sweep that erases personal data and disables the login while
keeping the financial records the law requires (money-flows and the ledger need the rows; they do
not need the name).

### Y.10 — The native projects are not store-ready (High, store)

Release signed with the debug key; no R8; labels `suskii_mobile` / `Suskii Mobile`; Android
`com.suskiierrands.suskii_mobile` vs iOS `com.suskiierrands.suskiiMobile`; no flavors; template
launcher icons; no splash; no network security config; no crash reporting; iOS has no privacy
manifest, no usage strings, no export-compliance key, no entitlements and no Podfile. Each is
itemised with its fix in `docs/runbooks/RB-15-store-release.md`.

### Y.11 — The web apps send no security headers (High)

**What.** None of the three `next.config.ts` files defines `headers()`, and there is no middleware.

**Consequence.** No CSP, HSTS, `frame-ancestors`, `nosniff` or referrer policy — the spec's web
security list (`security.web`) and ASVS V14 — on an admin console that moves money.

**Fix.** A shared header set, CSP included, applied to all three.

## Found by running it end to end (added 2026-09-28)

Everything above came from reading. These came from **running** it: the app's Supabase
repositories against a real local stack (`packages/suskii_data/test/integration`, 11 flows), and
seventeen-then-nineteen journeys driven through the real screens on the mock backend
(`apps/mobile/test/flows`). A deny test passes whether the denial is right or the allow clause was
never written (the lesson of audits U.1–V.1); a journey that never reached the end is the same
kind of blind spot, and most of these had been invisible to every review.

### Y.28 — Every money-moving call fails at COMMIT (Critical)

`ledger.entries_balanced` and `refunds_within_payment` are deferred constraint triggers (S-14).
They fire at COMMIT — after every `SECURITY DEFINER` function has returned — so they run as the
role that opened the transaction: `service_role` for the payment webhook, settlement, payouts and
chargebacks; `authenticated` for tips, cancellations and withdrawals. Neither may read the
`ledger` schema. **The first real payment webhook would have failed**, and so would every posting
after it. The refund check also read through the caller's RLS and could pass on rows it could not
see. pgTAP never saw it because a test transaction rolls back and deferred triggers never fire.
**Fixed** (`c3607f4`): both trigger functions are `SECURITY DEFINER` with an empty `search_path`;
`48_deferred_invariants_test` fires them as each calling role with `SET CONSTRAINTS ALL IMMEDIATE`.

### Y.26 — A first run on a real backend fails before anyone signs in (High)

Bootstrap asked for the unread-notification count while signed out; `anon` has no grant on
`notifications`, so the first screen of a fresh install was the startup error. With no country
chosen it also failed rather than falling back. **Fixed** (`3942226`, `1cf4f3a`).

### Y.27 — A phone sign-up without metadata can never post a request (Medium)

`create_request` refuses a profile with no country and no client grant can set one. **Fixed** on
both sides (`87dffec`, `3942226`): the app sends country and language as sign-up metadata, and
`handle_new_user` falls back to the longest matching calling code.

### Y.29 — No provider can ever mark arrival (High)

`set_job_status` refuses `arrived` unless the position is inside the pickup geofence or a manual
reason code comes with it (transition 13). The app sent neither. **Fixed** (`d2cd84e`): the device
position goes with the request; with no fix, a mocked fix, or a refusal outside the fence, the
provider confirms a manual arrival and the reason code goes on the record. The mock applies the
same 150 m rule.

### Y.30 — Erasing an account leaves the profile photo in storage (Medium)

`private.erase_account` cleared `avatar_path` and left the file. Storage refuses direct deletes
(`storage.protect_delete`), so **fixed** (`d4bc3de`) by queuing the folder on a new `storage`
outbox aggregate and removing it through the Storage API in `storage-worker`, which acts only on
an allowlisted bucket and only on the event's own user folder.

### Y.31 — Live tracking has neither end (High)

ADR-0009 puts the live position on the job's private Realtime channel with a sparse heartbeat.
No provider build sent a position or called `heartbeat`, and the customer's map (app and web) read
`location_samples`, which participants may read only after the job ends — so on a real backend the
map was empty for the whole job, and neither the trip trail nor the matching position was ever
written. **Fixed** (`d156e8c`): `publishProviderLocation` broadcasts `provider.location`
(contracts 1.3.0) and heartbeats at most every 30 s; both customer clients listen to the
broadcast. Foreground only (OD-27).

### Y.32 — The pay button fills the payment screen (High, visual)

`SButton` centred its label with a bare `Center`, which under a bottom bar's loose constraints
grows to the full height: the payment screen was one gradient slab. The golden recorded it and
nobody looked at it. **Fixed** (`3e884d5`) in the component, so everywhere.

### Y.33 — Screens that close themselves pop twice, or nothing (Medium)

Ending a call popped twice (the end button and the `ended` event), taking the request screen
with it; the payment screen started a new exit timer on every `held` emission; opened from a
notification, with nothing underneath, both threw. The call and voice screens read providers in
`dispose`, which Riverpod 3 forbids. **Fixed** (`350ee5d`): one guarded close and
`context.leave()`, which falls back to a route when there is nothing to pop.

### Y.34 — Smaller things the journeys hit (Low)

"Start journey" offered on a `paid_held` job the server refuses (transition 12 is from `assigned`);
earnings amounts broke mid-number; rated-job rows overflowed; `SecureScreen`'s documentation
promised an iOS app-switcher cover that nothing implemented. **All fixed** (`350ee5d`, `fff0820`).
