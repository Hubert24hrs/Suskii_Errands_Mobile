## Why it existed

[PHASE-1-PLAN](../../docs/plan/PHASE-1-PLAN.md) held contracts v1 until Kimi Code's M8.5 hand-off.
Both agents were building against the same error codes and enums long before then, so those pieces
were pinned early rather than guessed twice. M8.5 landed on 2026-09-21 and v1 followed on
2026-09-22.

## The four decisions it made, which v1 keeps

| # | Decision | Why |
|---|---|---|
| P-1 | Money on the wire is `{ amount_minor, currency }` | Matches the database columns (`*_minor` + `currency`) and the snake_case convention of the enums. Resolved review C.7 |
| P-2 | A phone number outside a supported country gets `ERR_COUNTRY_NOT_SUPPORTED`, not `ERR_COUNTRY_DISABLED` | It is what the backend raises; apps see it through Supabase Auth |
| P-3 | A withdrawal needing Finance approval is **not an error**: the call succeeds with a pending-approval status | The user did nothing wrong, and an error code would make the app show a failure |
| P-4 | `ERR_OTP_INVALID`, `ERR_OTP_RATE_LIMITED`, `ERR_NETWORK`, `ERR_UNKNOWN`, `ERR_FORCE_UPDATE_REQUIRED`, `ERR_VERIFICATION_FAILED` are app-side codes | The backend never sends them; the apps derive them from Auth errors, connectivity, bootstrap or the vendor SDK |
